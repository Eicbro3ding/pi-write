# 审稿标准（craft-review）

方法论文库 + 路由，不含流程指令，也不含「怎么审」的流程——那看 `critique` 技能。
本技能提供的是**判据与评分标准**。文字表达层的具体改法 → `craft-deslop`；正文技法 → `craft-prose`；
结构/大纲问题 → `craft-outline`。

## 怎么用

1. 按下面的路由表选**一份**。
2. `read` **整份**——两份文件都是清单体，跳读等于没查。
3. **判据是参考，不是戒尺**：本库给的是平台通行标准，用户刻意选定的 POV / 时态 / 语域不在此列，
   要评的是执行而不是前提。

## 路由表

| 你在做什么 | 读 |
|---|---|
| 逐项检查（章节结构 / 节奏 / 人物 / 情绪 / 文字，含长篇与短篇专项） | `review-quality.md` |
| 按平台标准打分（未指定平台时的默认 rubric；PASS/WARN/FAIL + Findings） | `quality-rubric.md` |

**典型用法**：用户说「评一下这一章」→ 先 `review-quality.md` 逐项过；他问「值多少分/能不能投」
→ 再上 `quality-rubric.md` 按平台打分。两份都读完通常够一次完整评析。

## 与 world.json 的关系

评「人物有没有崩」要对照 `world.json` 里的人物条目与关系，而不是只在正文里找；
评「节奏对不对」要对照大纲条目与本章细纲。上游那套「文件树当记忆」的 `设定/`、`剧情/`、
`拆文库/` 路径只是**内容组织思路**，别照着写文件。

## 本库不做什么

- **不含流程**：上游的多视角 agent 审稿、打分报告产线、`/story-setup` 都没有收进来；本库只有标准。
  正文里提到「跑 `scripts/xxx.py`」「读 `workflow-*.md`」的忽略即可——残留引用逐个登记在
  `references/ATTRIBUTION.md`（连同 MIT 许可证全文 `references/LICENSE-oh-story-claudecode.txt`），
  **不要去找那些不存在的文件**。
- **不代替读感**：清单与评分是提示与复核，不能替代真的把这一章读一遍。
- 本库不改稿：给建议 → `critique`；动手改 → `revise`。
