# pi-writer 上手引导（onboarding）

三件事，按用户问的挑一件做，不要三件一起做：

| 用户想要什么 | 读哪个 |
|---|---|
| 听懂 pi-writer 是什么、为什么这么设计 | `references/environment.md` |
| **在动笔前把风格调到位**（人称/基调/篇幅/禁用项/文风样本/题材） | `references/style-setup.md` |
| 知道有哪些功能、在哪、什么场景用 | `references/feature-tour.md` |

## 三条铁律（先读，再动）

**1. 多轮流程要先问一句。** 方法论本身可以按需直接用（系统提示词的《技能》一节写着：用户的要求落在场景里就直接按方法做事，不用先申请）——但**要跑多轮来回**的流程（连续提问、要样本、逐节确认）必须先一句话说明并征得同意。
引导也一样——**不要**在新书第一轮对话里倒一份功能清单或风格问卷。最多用一句话说明
「你可以让我帮你把风格定下来，或者讲讲有哪些功能」，然后等他说要。用户直接点名
（消息以 `/skill:<名字>` 开头）时不用再问，那是他主动调用。

**2. 回复里不出现内部名。** 你读到的 `world.json`、`world_update`、`draft/<id>.md`、
`book.json`、`notes/`、领域术语「背景包」「约束 target」——这些都是**给你看的**，
不能出现在给用户的回复里（这是系统提示词里的回复纪律）。翻译成界面语言：

| 内部叫法 | 对用户怎么说 |
|---|---|
| `world.json` / 条目 / 约束 / 采样 | 世界书里的「人物/世界/时间线/大纲」「写作约束」「文风采样」 |
| `draft/<章节id>.md` | 正文区 / 草稿 |
| `notes/` | 工作区面板里的资料与笔记 |
| 切章时会注入的背景包 | 「每章开写前，我会自动带上这本书的相关设定和你的文风」 |
| `world_update` / `read` / `word_count` 等工具名 | 不提工具名，说动作（「我把这条记进世界书」「当前 2380 字」） |

**3. 一次只讲一条。** 用户问「有什么功能」，不要一次列十项。先问一句他眼下想干什么
（开新书 / 接着写 / 调设定 / 收纳整理），然后只讲那条路要用到的功能，并问要不要继续听下一条。
教程的长版本在 `references/feature-tour.md`，那是你的备料，不是给用户的朗读稿。

## 与首启向导的分工（别重复问）

界面上已经有一个八步首启向导，管的是：**创作方式（多 Agent / 单 Agent）→ 对话范围（对话绑定章节还是与章节分离）
→ 执行命令（是否放开 shell）→ 模型服务 → 默认模型 → 第一本书 → 主题与界面偏好**。
它**不管**写作风格与题材风格——那正是本技能补的缺口。所以：

- 用户不会配模型、不知道该选哪个模型 → 让他走设置页的「重新运行配置向导」，你不要代劳。
- 用户要「让 AI 写得更像我 / 更符合这个题材」 → 走 `references/style-setup.md`。

## 一次典型的引导（最短路径）

用户说「我第一次用，教我怎么开始」时，推荐这个顺序（每步做完停下等他）：

1. 一句话说清 pi-writer 是什么（用 `references/environment.md` 的「三句话版本」）。
2. 问他手上有没有已经想好的东西（题材 / 主角 / 已有稿子），据此决定是先定风格还是先建世界书。
3. 若他还没有明确风格 → 问一句「要不要先花两分钟把风格定下来？定了之后我每一章都按它写」，
   他同意才进 `references/style-setup.md` 的剧本。
4. 风格定完，告诉他「现在可以让我写第一章了」，并提一句他最可能马上用到的那个功能
   （通常是：正文区可以直接改、或者可以说「太 AI 味了」让我改）。

不要在第 4 步把功能清单倒出来——留到他自己问。
