# 风格引导剧本（动笔前把风格定下来）

目标：把用户嘴里模糊的「我想要那种感觉」变成**四条以后每章都生效的硬设定**，
并且**真的写进世界书**——不是聊完就散。

## 什么时候走这个剧本

走：
- 用户说「让 AI 写得像我 / 像某个风格 / 符合这个题材」「文风不对」「第一人称」。
- 新书第一次对话，且这本书还没有任何风格设定（下面第 0 步会查）。
- 用户已经写了但一直在手改同一个毛病（人称跳、太啰嗦、太 AI）→ 那是缺硬约束。

不走：
- 用户只想改**某一段**文字 → 走改稿流程（`revise` 技能），不要顺手改全书风格。
- 用户想换的是模型、随机性、思考深度 → 那是设置页的事，指路即可，不要混进风格设定。

## 第 0 步：先看这本书有没有风格设定（不要凭空重问）

查一遍现有世界书：世界观概述、写作约束、文风采样是否为空。

- **采样要用 `read_style` 查**（它不常驻上下文，看不见那个块**不等于**没有——调一次确认）。

- **已有** → 先把现状用自然语言复述给用户（「你这本现在是第三人称、每章 2500 字上下、
  文风采样取的是第二章那段」），再问他想改哪一项。**不要**把已有的问一遍。
- **为空** → 进第 1 步。

## 第 1 步：一轮问清（一次问完，别拆成多轮）

用 `ask_user` 一次问 4 个（这是它的上限，也能让用户一次点完）。**每个都要给 2–4 个候选，
并且允许他自己补充**——候选只是省他打字：

| 问什么 | 候选示例 | 落成什么 |
|---|---|---|
| 这本是哪个路子的题材？ | 都市脑洞 / 玄幻升级 / 悬疑灵异 / 言情（让他补具体） | 世界观概述 + 题材卡 |
| 用什么人称和视角？ | 第三人称限知 / 第一人称 / 第三人称全知 / 还没定 | 写作约束 |
| 想要什么基调和节奏？ | 快节奏爽感 / 慢热细腻 / 沉重压抑 / 轻松诙谐 | 写作约束 |
| 一章大概多长、多久一更？ | 2000 字上下日更 / 3000–4000 字 / 5000+ 字 / 随缘 | 写作约束 |

他答不上来时不要追问，取你能给的最合理默认，并在复述时明确说「我先按 X 定，随时改」。
**尤其不要替他定题材**——题材是他最在意的那个决定。

## 第 2 步：文风样本（这一步最值钱，别跳过）

问他要一段 **300–500 字**的文字：他自己写的，或者他想靠近的某个作品的片段。

- 有样本 → 用 `world_update` 的 `update_style_sample` 存下来（出处写清是「用户提供」还是「来自某作品」）。
  这是让「写得像他」真正生效的机制，比任何形容词都管用。
- 没有样本 → 给两条路让他选：① 先按题材的通行写法写一章，他改完之后**从改稿里回采**样本
  （章节收尾时你自己判断，这本来就属于你的自主维护范围）；② 他口述「像谁」，你据此写，但明确告诉他
  「你亲手给一段会更准」。
- **绝不编造样本**，也不要从别处抄一段冒充他的文风。

## 第 3 步：落盘（把话变成设定）

用户的回答本身就是确认，可以直接写，但**每一笔都要在回复里用自然语言讲清**。用你手上的世界书写工具——
三个 op 名（`set_world_summary` / `upsert_constraint` / `update_style_sample`）在 `world_update` 与
编剧专用的 `style_update` 上是同一套，照名字调即可；你手上没有 `world_update` 时用 `style_update`。

1. `set_world_summary` —— 一两句：题材 + 基调定位（如「都市脑洞轻喜剧，主角靠信息差反复翻盘，节奏快」）。
2. `upsert_constraint` —— 把第 1 步的答案写成独立几条。**默认生效范围用「编剧」**：
   动笔写正文的是编剧（多 Agent 下的收幕成文与编辑页对话，单 Agent 下的写作 agent），
   导演管的是节奏与调度，不该被写作风格绑住。只有用户明确说「连剧本和演出也要守」时才用「全部」。

   各范围谁会收到：

   | 范围 | 谁会收到 |
   |---|---|
   | 编剧（**默认**） | 收幕成文、编辑页对话、单 Agent 的写作 agent |
   | 主会话 | 主会话 / 写作 agent |
   | 导演 | 只有导演 |
   | 全部 | 所有人 |

   用户不会说"target"这个词，别拿它问用户——他只是想"以后都这样写"，默认给「编剧」就对了。
   编剧自己的窄工具（`style_update`）只会写「编剧」范围，这也正是默认值。
3. `update_style_sample` —— 第 2 步的样本。
4. 可选：`upsert_entry(type: "world")` 写一份题材定位/对标（用户提到对标作品时才写）。

**约束要写成可判定的**（这是最容易做砸的一步）：

| 不要写 | 要写成 |
|---|---|
| 文笔要优美 | 每段不超过 3 句；不用形容词堆叠 |
| 节奏要快 | 每章至少一次反转；章尾必须留钩子 |
| 不要 AI 味 | 禁用「不是…而是…」「仿佛」「缓缓」「微微」；不用破折号 |
| 人物要立体 | 每个主要配角有一条与主角冲突的诉求 |

条数控制在 **8 条以内**——约束太多会互相打架，而且挤占每章的上下文预算。宁少而硬。

## 第 4 步：复述（用他的话，不用你的字段）

定完给一段简短确认，形如：

> 记下了：都市脑洞、第三人称限知、节奏快、每章 2500 字上下；
> 三条硬规矩——不用破折号、禁用那几句 AI 腔、章尾必须留钩子；
> 文风采样用的是你给的那段。以后每章我都按这套写，随时可以改。

**不出现**「约束」「采样」「target」「世界观概述」这类内部叫法，也不要报任何路径。

## 第 5 步：收口与后续

- 告诉他怎么自己改：世界书页里有「写作约束」「文风采样」两处，可以开关、改文字、换样本。
- **提醒他改完立即生效**——下一章开写就会带上，不用重启或重新配置。
- 如果他说「写出来还是不对」，先别加约束——让他指出一段具体不满意的文字，
  那通常能直接定位到缺的是哪一条规矩（人称跳？太啰嗦？没有钩子？）。

## 别做的事

- **这四连问要走完整轮，所以先问一句。** 它不是「读一份文件照做」而是一串来回（四问 → 要样本 → 逐条确认落盘）：按系统提示词的《技能》一节，**多轮流程先一句话说明并征得同意**再开始。用户主动点名（`/skill:onboarding`）时不用再问。
- **不碰采样参数与思考级别。** 用户抱怨「太保守/太飘」时指他去设置页，你不代改。
- **不把题材卡整份塞进约束。** 题材正文卡是给你写的时候参照的，只把用户确认过的几条变成约束，
  其余写作时按需重读 `craft-outline` 技能里的对应题材卡。
- **不承诺你做不到的**（自动发布、投稿、联网查资料），除非那些能力真的挂在当前会话里。
