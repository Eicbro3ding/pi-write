# 去 AI 味与文风（craft-deslop）

方法论文库 + 路由，不含流程指令。改稿的落笔纪律（外科式 edit、不整章重写）看 `revise` 技能，
本技能只管「往哪个方向改、怎么判定」。正文技法 → `craft-prose`；结构/大纲 → `craft-outline`。

## 怎么用

1. 按下面的路由表定位**一份**文件（最多两份）。去 AI 味是「主文件 + 速查表」两件套时最有效。
2. `read` **整份**。`anti-ai-writing.md` 开头有决策路由与改写顺序，跳读会漏掉判据。
3. **方法是参考，不是覆盖**：用户当前要求 > 本书 `world.json` 里的文风采样与写作约束 >
   本库默认值。本库给的是通行做法，不是这位作者的文风。

## 路由表

| 你要做什么 | 读 |
|---|---|
| **去 AI 味主文件**：AI 写作指纹、核心规则、10 种模式检测、改写顺序、范例库、质量清单 | `anti-ai-writing.md` |
| Gate 执行细则：哪条 blocking、哪条只提示、怎么判定与放行 | `deslop-gates.md` |
| 禁用词与句式速查表（逐条匹配已知模板；改写时对照） | `banned-words.md` |
| 文笔：镜头式写作、白描、视角、毒点规避、开篇定调 | `style-craft.md` |
| 装逼打脸与爽点释放（写/改这类场景时，怕写不到位） | `style-combat-face.md` |
| 按题材取风格模块（各题材的核心原则与关键技法） | `style-genre-modules.md` |
| **文风裁决**：当前请求、本书文风、作者偏好、对标文风冲突时按什么顺序取值 | `style-resolution.md` |

**典型组合**：用户说「太 AI 味了」→ `anti-ai-writing.md` +（要逐句对照时）`banned-words.md`。
用户说「改成我的文风」→ `style-resolution.md` + `style-craft.md`。

## 与 world.json 的关系

文风在 pi-write 里有真实落点：**文风采样**（`world.json` 的 `styleSample`，每章开写前注入）
与**写作约束**（`constraints`）。判断「这本书本来是什么声线」要看它们，而不是只看这段文字。
上游那套「文件树当记忆」的 `设定/`、`追踪/`、`文案/` 路径只是**内容组织思路**，别照着写文件。

## 本库不做什么

- **不含流程**：上游的 hook 门禁（`deslop-gates` 只是判定标准，不是可执行门禁）、专业 agent、
  `/story-setup` 都没有收进来。正文里提到「跑 `scripts/xxx.py`」「读 `workflow-*.md`」的忽略即可——
  残留引用逐个登记在 `references/ATTRIBUTION.md`（连同 MIT 许可证全文
  `references/LICENSE-oh-story-claudecode.txt`），**不要去找那些不存在的文件**。
- **去味的目标是读感，不是过检测器**：不要为了降低某个 AI 检测分而牺牲人物声音与场景任务。
- 本库只提供方法：改稿落笔看 `revise`，评析看 `critique`。
